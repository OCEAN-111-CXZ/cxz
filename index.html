童装补货看板

近7 + 近15 + 近30 天销售明细 + 库存表 → 自动合并 · 动态周转 / 色码结构 / 备货周期倒推　v9 · 2026-11-13

把 4 个文件拖进来就行

聚水潭「销售主题分析 → 供销明细汇总」导三次（7 天 / 15 天 / 30 天），加一份「库存 → 商品库存查询」。支持 .xlsx / .csv，直接在浏览器里解析，不上传任何服务器。

列对应关系

三张销售表结构相同，改一处三张一起生效。标红=这张表里没这个字段。

文件里都认哪些字段

销售明细（7 / 15 / 30 天三份）
  • 需要：款式编码、商品编码、颜色规格（“黑色;170”一列也行，自动拆）、销售数量、退货数量。
  • 有就用、没有也不影响：虚拟分类（用来判当季/过季）、产品分类、净销售额（估成本用）。
  • 三份表按 商品编码 自动对齐，不用你手工合表。
库存表
  • 需要：商品编码、可用库存。用「可用库存」，不要用「实物库存」——可用已扣锁定和预占。
  • 有更好：采购在途（防重复下单）、成本价（算货款）、款式编码、颜色规格。
文件打不开 / 报错怎么办
  • 只支持 .xlsx 和 .csv。如果提示“旧版 .xls”，用 Excel/WPS 打开后「另存为 → .xlsx」再拖进来。
  • 表头不在第一行也能认（会自动跳过前面的标题行），但一张表只能有一个表头。
  • 列名被改过（比如把“销售数量”改成“销量”）也能识别常见别名；实在认不出，在「列对应关系」里手动指一下。

补货参数

改完立刻重算。这几个数决定“补多少”，按自己供应链的实际情况调。

权重三项相加建议 = 1.0

大促备货

活动期日销是平时的几倍。填了日期和倍数，落在备货窗口内的活动会自动加进目标库存；填了也不算，说明活动在窗口外（备货来不及，或还早）。

双11/双12 常见 3~8 倍；聚划算 2~3 倍；只填几天的话指那几天的倍数。

主推款（可选）

把这季主推的款号贴进来（逗号、空格、换行都行），它们的优先级会自动加权，不会和普通当季款混排。

算法说明

  • 需求日均 = 0.5×近7天日均 + 0.3×近15天日均 + 0.2×近30天日均，再乘 (1−退货率)。某个周期没导就不参与，权重自动归一。
  • 断货校正（关键）：可售÷加权日均 < 3 天时，说明正在断货、销量被压制，改用 MAX(加权日均, 30天日均×0.85)。不校正的话，断货款销量是“假低”，会得出“库存还够”的错误结论。
  • 可售天数 = (可用库存 + 采购在途) ÷ 需求日均。这是全表的核心刻度。
  • 补货点 = 需求日均 × 备货周期 + 安全库存；目标库存 = 需求日均 × (备货周期 + 覆盖天数) × 大促系数。
  • 建议补货量 = MAX(0, 目标库存 − 可售 − 在途)，向上取整到补货基数，不低于 MOQ。
  • 最晚下单日 = 今天 + (可售天数 − 备货周期)。超过这天再下单，货到之前就断了。
  • 状态等级：P0 = 可售天数 ≤ 备货周期（到货前必断）；P1 ≤ 备货周期+7 天；P2 = 关注；充足；不补。
  • 色码结构：主卖色(码)销量占比 ≥ 阈值、但库存占比 < 销量占比×0.7 → “主卖色/码偏少”。总量够也必须补这个色/码。
  • 退货率向全店均值收缩，避免“卖 5 件退 3 件”被算成 60%。
